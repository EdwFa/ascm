# ASCM: Atomic Semantic Chunking for Medical RAG

Точная чанкинг-оптимизация клинических рекомендаций: предложения, связанные защищёнными границами F
(рекомендация ↔ строка УУР/УДД, пункты нумерованных списков), сливаются в **атомы**; разбиение атомов на чанки
находится динамическим программированием за O(N·K·d) и оптимально *относительно заданной целевой функции*
(не «абсолютно лучшее» разбиение для всех задач).

Корпус: 8 российских клинических рекомендаций (Минздрав РФ), см. `data/raw`. Статья: «Atomic Semantic Chunking for Medical Retrieval-Augmented Generation».

## Запуск

```bash
python -m pip install -r requirements.txt
python scripts/build_corpus.py                         # предложения, F, атомы -> data/processed, results/corpus_stats.csv
python -m pytest -q
# 39 тестов, в т.ч. ДП = полный перебор
python scripts/run_experiment.py                       # отладка: офлайн-эмбеддинги hash (НЕ для статьи)
python scripts/make_seed_passages.py                   # заготовки для врачей -> results/annotation/
```

Расчёты для статьи (нужен интернет и `pip install sentence-transformers torch`):

```bash
python scripts/build_corpus.py --tokenizer bge-m3
python scripts/run_experiment.py --embedder bge-m3 --eval-embedder e5
```

Чанкер использует BGE-M3, метрика SCS считается другой моделью (multilingual-e5-large), чтобы избежать круговой зависимости.

## Состав

| Путь | Назначение |
|---|---|
| `src/ascm/text.py` | нормализация, абзацы, предложения (русские сокращения) |
| `src/ascm/loc.py` | устойчивый детектор «Уровень убедительности рекомендаций … (уровень достоверности доказательств …)» |
| `src/ascm/atoms.py` | предложения, защищённые границы F, атомы, пары «рекомендация – УУР/УДД» |
| `src/ascm/dp.py` | функция стоимости Φ, точное ДП, жадная B7, перебор для тестов |
| `src/ascm/baselines.py` | B1 fixed, B2 recursive, B3 semantic, B4 header, ablation atom-fill |
| `src/ascm/metrics.py` | размеры чанков, ERL, разрезанные списки, нарушения F, SCS |
| `src/ascm/stats.py` | кластерный бутстрап по документам, перестановочный тест, поправка Холма |
| `src/ascm/retrieval.py` | span recall, Hit, MRR, evidence-linked recall (когда будут вопросы) |
| `configs/default.json` | веса Φ, τ\*, T_max, 4 фолда по документам |

## Варианты ASCM

| Метод | Эмбеддинги для C_sem и P_coh | Структурная стоимость границы |
|---|---|---|
| `ASCM_basic` | исходные | 0 на границе абзаца, 1 внутри абзаца |
| `ASCM_struct` | исходные | иерархическая: начало раздела дёшево (по глубине), отрыв блока «Комментарии» дорог (0,8), обычный абзац 0,5, абзац после законченной рекомендации 0,3 |
| `ASCM_center` | центрированные (вычтено среднее по документу) | как в basic |
| `ASCM` | центрированные | иерархическая |

`B7_greedy` использует ту же Φ, что и полный `ASCM`. Метрики `sec_cross`, `section_cut`, `comment_sep` частично оптимизируются иерархической стоимостью по построению, поэтому они не доказывают выигрыш в поиске.

## Что сделано и что нет

- Корпус обработан: 5 528 предложений, 4 436 атомов, 1 092 защищённые границы, 735 из 741 строк УУР/УДД найдено автоматически; атомов длиннее T_max нет.
- Все методы запускаются, ASCM и B7 дают 0 нарушений F. **ERL = 100% у методов с F по построению**, это не независимый результат; независимая проверка F на выборке вручную нужна.
- Числа, полученные с `--embedder hash`, служат только для проверки кода.
- Не реализовано: B5 parent-document, B6 TextTiling, EPR (нужен детектор сущностей UMLS/SNOMED), подбор весов Φ на dev-документах (нужны вопросы), генерация и оценка ответов.
- Токены по умолчанию оцениваются словесной прокси; для статьи собирайте корпус с `--tokenizer bge-m3` (208 106 токенов, максимальный атом 651).
- Сегментатор правиловый: сокращения из списка (`мг.`, `см.` и т.п.) не считаются концом предложения.
